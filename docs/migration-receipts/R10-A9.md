# R10-A9: pure workflow dependency trees

Delivered locally on the existing R10 branch on 2026-11-16, based on `b6057b2`.
This slice adds pure dependency resolution, bounded missing-reference diagnostics,
access summaries, direct-reference lookup and subtree projection. It adds no
storage adapter, public ctl operation, capability or execution path. A10 catalog
operations and A11 run snapshots remain outstanding.

## Behavior and review

Resolution uses an explicit stack and memoizes completed expansions by maximum
depth. It preserves first pin/edge order, maximum access depth and cycle/error
ordering. Diagnostics traverse occurrences separately and retain report, visit,
encoded-byte, identifier and display limits. Subtrees retain parent insertion
order, the accepted P13 choice for Python's set-derived mapping order.

Independent review found recursive hashing/cloning could precede depth refusal;
iterative input-depth checks now run first. The actual Python oracle then exposed
an omitted identifier in fifth-level nesting error text. Rust now preserves
Python's exact fallback behavior, including an already pinned child. Both code
reviewers closed without remaining actionable findings.

## Validation

- Final full workspace gate: 2,014 passed, zero failed, 63 ignored; 294 summaries.
  This branch does not contain the later recovery commits on main; its count is
  not the main-branch gate count.
- Fifteen focused reference/tree tests cover unequal-depth diamonds, cycles,
  first-error order, duplicate identities, depth and diagnostic bounds, Unicode,
  strict boolean network access and subtree ordering.
- One host parity test checks seven Python-oracle cases. The fixture records the
  reference commit `14f0c1fe7e9f4734eb7b9a299b65666e0d4f72b8` and source SHA-256.
  Generation uses pure functions and an in-memory catalog, without constructing
  a store or accessing live state. The source hash was independently checked.
- Formatting, architecture and legacy-name guards and full all-target clippy
  with warnings denied passed on the final tree.
- One temporary release timing probe used definitions with 1,000/1,000/1,000/2
  nodes, 998 repeated references per expanding definition and four levels. It
  observed validation 24.57 ms, resolution 132.10 ms and subtree 2.16 ms, producing
  four workflows and 2,994 edges. The probe was removed; this is a local timing
  observation, not an approved performance threshold.

No provider call, live-state mutation, push, release or production cutover was
performed. The full gate ran outside the sandbox because process tests require
kernel boot-identity access.
