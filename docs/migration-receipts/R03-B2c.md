## Delivered design

See [capture/completion](../capture-completion.md) for the exact protocol, inventory
and limits. Fresh schema4 adds capture_meta, capture_records and capture_events;
older schema3 roots refuse without upgrade or repair. All writes retain existing
FULL/WAL/binding/admission behavior. No dependency or Cargo.lock change is needed.

The owner consumes EffectDone exactly, then captures only the deterministic raw
suffix; framed protocol bytes are excluded. It retains the original direct child,
closes every Store per command and holds no storage lock across a pipe/gate/process
wait. Raw files are created after child spawn, exclusively with nofollow, regular
single-link shape, device/inode checks and nonblocking locks. Directory sync precedes
zero-offset metadata. Append validates lengths/identities, writes and syncs both
streams, revalidates sources and the original deadline, then returns offsets.
Any failure poisons that raw adapter. No uncertain tail is replayed, reopened,
truncated, repaired or silently indexed.

Capture binding includes the complete acceptance fence, original child and distinct
raw file identities. Every mutation revalidates the current owner/child/fence and
capture revision. Progress offsets and their private event commit atomically; final
exit and its event commit atomically. Terminal is immutable and requires published
both-EOF/no-loss state plus an observed exit code or positive signal. Host finish
uses only synced/published bytes and the retained child's wait result. Immediately
after the pre-terminal gate, both raw sources and lengths are freshly rechecked.
These are cooperative filesystem checks and trusted internal observations, not a
hostile-writer/authentication proof.

Acceptance remains distinct from completion. Completion precedes final Accepted
send, so acknowledgment failure does not interrupt remaining capture. No ownership
phase/revision is changed by capture; no release, owner-dead or complete-containment
proof is manufactured. The durable reservation still excludes replacement.

## Bounds and failure disposition

- Raw total65536bytes per stream, append at most16384bytes per stream; pump32768
  total read budget shares16384 with each stream. Taking bytes preserves EOF/error/
  overflow separately. No background queue or worker thread exists.
- At most128 private events per operation including terminal; extreme fragmentation
  may refuse below the byte cap. Reads preflight bounded fields before allocation;
  writes check Store limits, scalar conversions and revision overflow.
- Slow persistence stops pumping and applies ordinary pipe backpressure. Existing
  parent/owner/effect10/8/4second budgets and separately bounded qualified cleanup
  remain. Filesystem/kernel/SQLite calls are nonpreemptible; no hard arbitrary-I/O
  wall-clock, RSS, throughput, p99, scale or general process-tree claim follows.
- Raw sync failure/late result, overflow, pipe error, stale fence/revision, source
  replacement and incomplete drain cannot publish lossless terminal. Already admitted
  SQLite commits retain their existing committed-or-unknown result semantics, including
  a possibly late committed result; never infer retry permission.
