# R10-A11: pure immutable workflow snapshots

Delivered locally on the existing workflow branch on 2026-11-16, based on
`14d6275`. Launch normalization, supplied-pin snapshot preparation and resource
scope validation are pure operations. No storage adapter, ctl command, public
capability, provider invocation or runtime adoption is introduced.

## Behavior

`launch_definition` copies the root and forces bounded context. A backend change
removes exactly six backend-specific settings before merging overrides and
validating; backend defaults may be reintroduced by normalization. Nonempty
orchestrator overrides expect a normalized stored root.

`prepare_snapshot` preserves canonical Python ordering: source-name check, launch
normalization, original pinned definitions validated and hashed in insertion order,
root name/hash comparison, then a copied tree whose definitions all force
`optimized_v1` and are rehashed. Normalized pin validation output is discarded;
original shapes and metadata survive except the explicit context/hash rewrite.
The supplied tree must already correspond to the launched root including overrides.
Borrowed depth guards precede recursive copies/hashes, including revision metadata,
without suppressing an earlier name, validation or hash refusal.

Resource scopes follow definition nodes and on-demand nodes rather than cached
edges. Unconstrained and explicitly empty declarations stay distinct. Every
invocation inherits its enclosing declaration; shared children are checked under
each scope and label. Iterative traversal checks cycle/depth before completed
context memoization; deeper revisits cannot reuse a shallower successful expansion.
Inputs remain unchanged on success and refusal. Refusals are structured and rendered
with the corresponding Python messages.
