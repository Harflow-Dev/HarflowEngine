# R06-A — Offline same-context conversation ledger

Date: 2026-11-06. Status: private fixture ledger implemented, verified locally and
committed locally. It is not accepted. R05 remains unqualified, R06 overall remains
open, and public bounds parity is deferred. Nothing here was pushed or released.

## Scope

R06-A is a standalone, same-context, Queue-only fixture ledger over constructor-injected
ports. It is not a working conversational backend. It adds no delivery, spawn or input
transport, no public ctl operation or capability, and no production evidence adapter.
Now, promotion, interrupt, Fresh, Resume, automatic, workflow and steering routes refuse
before port I/O. Canonical semantics are HarflowMCP 0.0.11 at
`6195e619499003301e4b20bacc3da86b5dbe371a`. Its persistence model was not copied, and
builds and tests do not read the sibling checkout. Storage reuses schema-5
`fixture_records` under reserved `__r06/` keys with the bounded `HFCQ1` binary frame; no
dependency or table was added.

## Corrections made to the earlier candidate

Source review against the canonical documents changed the WIP commit `60dd4a1`:

- Unknown on a Consumed message is an idempotent no-op, as canonical `mark_unknown` is.
- Any witness epoch mismatch is Expired, as canonical `request_expired` is.
- Boundary evidence is first-wins and keeps its original epoch. The same evidence id is a
  no-op and a different id is a conflict; previously a later observation overwrote it.
- A runtime fault must name the current generation and turn, so a late report cannot
  fault a later turn. Epoch is not compared, so compaction cannot drop a same-turn report.
- Closed ledgers refuse boundary and acknowledgement writes.
- Interrupt, Workflow and Steering routes exist so they refuse explicitly.
- `conversation_observe` is a read transaction that cannot report an unknown commit.
- Frame validation now ties claims to the current generation and turn, enforces FIFO and
  issuance bounds, and derives `history_floor` from the retained set in O(retained) work.

The earlier storage cut test was also defective: the hook fired on the child's observe
rather than its mutation, so the before-commit case passed vacuously and the after-commit
case failed. The actor harness was rewritten with bounded reads and kill on drop.

## Limits

- Hostile raw SQLite writes and mixed older writers are outside this cooperative fixture
  guarantee. `Store::conversation_apply` and `Command` are public within the crates; no
  host or interface caller exists, and the oracle boundary is the application service.
- A store needs `Limits.max_bytes` of at least 4 MiB. Default limits refuse enrollment and
  new sends, failing closed, because each frame is checked with the 1 MiB completion reserve.
- Binary bounds do not establish canonical public JSON bounds. Escaping can expand text;
  an escape-heavy verbatim case is covered without any parity claim.
- A retired claim UUID presented with a current witness can mint a new grant. Its exact
  replay carries the old epoch and is Expired, so a lost-reply retry cannot obtain one.
- Source revision is checked only against the enrolled floor. No highest-seen revision is
  stored, so regression above that floor is undetectable. The below-floor test asserts
  refusal only and does not isolate that branch.
- For an accepted row, `revision_valid` makes the fence comparison redundant with the
  cancelled flag. The tests prove the combined refusal, not each clause separately.
- Cross-process tests use the test lease adapter, whose try-lock returns Busy. They are
  not cross-process lock qualification, which belongs to hf-platform.
- Deliberate differences from canonical: boundary refuses while Claimed or Unknown and on
  a closed ledger; fault on a closed ledger refuses; refusal ordering among stale, fault
  and invalid differs, though each refuses without mutation. Retention counts cancel UUIDs
  toward 64 receipts, as the root-level decision allows, so the `bounded-window` vector's
  64 retained cancelled entries are not reproduced. No response prose, accounting or
  progress is modelled, so no settled-response-turn limit applies.

## Canonical vectors

`crates/hf-interfaces/tests/conversation_vectors.rs` reads only the vendored
`tests/fixtures/contracts-v1/`. `empty`, `closed`, `queue-fifo`, `queue-replayed`,
`cancelled` and `cancel-replayed` are compared through a normalized projection.
`consumed-synthetic`, `delivery-unknown` and `unknown-reconciled-synthetic` use Now
delivery, so only status vocabulary and destination generation and turn are compared. **No
canonical Queue-consumed vector exists.** Refusal vectors hold only a code with no trigger
scenario, so that table checks code vocabulary, not trigger parity. This is not production
or public parity.
