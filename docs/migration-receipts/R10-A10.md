# R10-A10: pure workflow catalog operations

Delivered locally on the existing workflow branch on 2026-11-16, based on
`8c542df`. Save, get, list and delete now operate through the injected definition
store ports. No SQLite adapter, ctl command, public capability or live-state writer
is introduced. A11 snapshots and R10-B composition remain outstanding.

## Behavior

Save preserves the accepted ordering: candidate validation, transaction admission,
identity check, delivery/execution defaults, arbitrary-precision revision check,
identity preservation or minting, dependency resolution, display-name pins,
authority admission, timestamp and final stored-document qualification before
replacement. A 4,300-digit revision carry is refused without replacement, with the
reader's decode reason rather than Python's hashing error and before the catalog is
listed (accepted divergence, R10-A addendum item 2 in
[R10-A decisions](../decisions/R10-A-workflow-definitions.md)). The
shared integer limit also prevents overlong integers reaching stored qualification.

Execution defaults use raw field presence and retain historical node modes. New
resource-bearing agents default to headless, an accepted divergence from Python's
save refusal (owner decision R10-A D6). An existing prefer-subagent node
that gains resources is refused rather than silently changing its mode.

Get reads only its named source; list and save's dependency index refuse corrupt
sources as a whole. Sources are qualified before recursive projection or hashing.
Delete still removes a referenced definition and returns a sorted reference notice
excluding itself. Injected store failures remain distinct from authored-input,
dependency and authority refusals.

of parity with Python's filesystem-path exception; final public mapping belongs
to R10-B. Concrete storage adapters still own envelope/version policy, encoded
source bounds, transaction behavior and effects. These tests establish the pure
use cases, not production storage or public workflow-operation qualification.
