## Supported mechanics

D1 already retains one exact OwnerSession, Store/root lease and original direct
child across the private fixed-helper lifecycle. D2 adds independently bounded
output drainage and a private OwnerChild guard declared after the retained session.
The guard covers normal/error/unwind paths: reader settlement and independent
original-child settlement precede Store/root teardown. An unresolved actor takes
the private fail-closed process path. No reader is detached and no join waits on
an unfinished thread without a deadline.

The original execution deadline is supplied once. Reader lifetime is bounded by
that deadline and its own8s cap; dispatcher10s and effect4s remain fixed. A read-only
ReaderView carries no stop/discard/input/session/Store control. Dropping or replacing
an observer cannot enroll another owner, reset the deadline, acquire pipe/wait
ownership or mutate the durable generation. Existing dispatcher-loss and observer-
restart external fixtures remain relevant independent evidence.

Cleanup has a separate budget: reader finished checks use at most1s; existing
qualified child cleanup has up to2s initial wait, then up to2s each after TERM/KILL.
These are work/admission limits around nonpreemptible OS calls, not a universal
wall-clock guarantee. A main-thread storage call that never returns prevents bounded
owner shutdown while retaining the Store/root lease. No bounded indefinite-I/O
shutdown or process-isolated storage implementation is claimed.

Independent architecture review found no useful additional production lifetime
abstraction under the accepted fixed-helper semantics. Adding a duplicate deadline
wrapper would not qualify the missing caller or runtime policies.
