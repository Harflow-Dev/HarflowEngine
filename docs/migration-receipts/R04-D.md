## Reviewed plan and retained authority

Fresh independent plan review accepted the smaller integrated D1 slice with three
requirements: a stateful narrow core rather than a Store wrapper, correct per-process
FD accounting, and truthful synchronous capture limits. Review caught a constructor
lifetime problem: ambiguous claim must not destroy the owned Store. The selected
construction holds the port without authority before a separate mutable claim.

Application OwnerSession owns a private narrow OwnerPort, exact request/owner/revision,
current fence and capture state. It has no fixture/frame dependency, port escape,
cancel/release operation, clone or constructor from a stored observation. Only a
successful exact Prepared/CAS claim permits spawn observation and acceptance.
Every port error or malformed write result permanently poisons further mutations
while retaining the port. Snapshots are last validated observations, not new authority.

Storage forwards this port to existing fenced transactions. Host still qualifies
the actual owner and complete private inherited preparation before construction;
these trusted fixed-helper checks do not qualify production transport authentication.
Owner opens Store once and retains its root lease through claim, original-child
spawn/identity, acceptance, capture, cleanup and final acknowledgement. No transaction,
connection mutex or io.lock spans a process/channel/gate wait. The original child
retains its input, capture pipes and sole waiter. Unknown cleanup/admission exits
the private owner without first unwinding the held Store. Owner death grants no
replacement, release, replay or pipe adoption.

Dispatcher/observer loss does not create another session or extend budgets. Fresh
observation uses the existing bounded read-only inspector, not OwnerSession. The
private final acceptance frame still follows capture in this fixed protocol; this
does not establish the timing or availability of a supported public run operation.

Before claim/spawn, the owner prewarms two operation-derived raw sentinels by bounded
acquire/drop. Permanent coordinator entries then guarantee later reuse needs no new
slot if identity is unchanged. Normal owner uses Store2+raw2=4 sentinels. Its child
separately uses Store2+ledger1=3 in a fresh process; no owner FD reservation is
transferred through spawn. Prewarm performs at most2 attempts, creates no executable
authority and does not release the durable reservation on partial failure.

Two deny-only private fault values extend the internal fixture codec:3 fills the
existing owner pool with254 fixed sentinels after Store's2, so prewarm fails before
claim/child;4 selects a helper that attempts73728 bytes per stream. Neither value
selects arbitrary commands or changes the canonical public fixture bundle. Saturation
qualifies bounded refusal/incomplete capture only, not independent backpressure/drain.

The existing private protocol reports uncertain/refused execution after failures;
its exit2 is not a public ctl usage/refusal classification or proof of non-execution.
The independent case oracle must establish any pre-spawn assertion. Ambiguous writes
can have committed: no automatic second mutation or launch is permitted. Loss can
leave persisted exit Unobserved even when the live owned child was reaped. Exit,
drain, loss, input reconciliation, terminal and containment remain separate facts.

All synchronous OS/storage work is nonpreemptible; bounds are admission/work limits,
not hard I/O completion or power/storage-fault guarantees. Same physical inherited
CWD only; fresh private bootstrap precedes Store/threads. Separate headless process/
group survival is tested, not general terminal/session daemonization or service support.
