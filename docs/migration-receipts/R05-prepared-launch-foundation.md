preparation binds exact policy/configuration/request, original caller, observed
executable, physical root/CWD/source and ledger. Unknown assignment and arbitrary
or Claude execution are not dispatch options. HFPL1 is prepared only after fresh
schema5 initialization; initialization cannot rewrite an already bound generation.
Legacy HFOP1 bytes, schemas and selection remain separate.

The existing claim CAS, original child/wait/control handles and capture ordering
are preserved. The new helper performs only the existing fixed effect class and
emits deterministic text-only protocol records. This is an actual local helper
process, not a provider or a Claude invocation.

The original owner hashes the raw tail before immutable append submission. A
volatile private CaptureAccepted commitment is issued only after healthy final
capture, acknowledged writes, reconciled input/FIFO/reader, zero exits of both
original children and closed writer channels. The parent consumes the original
one-use private delivery through ExactCaptureReader before forwarding its receipt.
Current qualified store snapshots, raw extents/identities/bookends and original
byte commitments must agree. Stored records cannot reconstruct a missing receipt;
changed or same-length-rewritten bytes refuse.

The current event-history digest is an interval-consistency witness, not an
original event-log commitment. Executable observations are on-disk path bookends,
not atomic fd-exec or mapped-image proof. Those limits remain explicit.
